## 5. 요구사항을 넘어 추가한 것

과제에 없었으나 실사용 관점에서 필요하다고 판단해 구현한 항목입니다.

- **상호 TLS 1.3 + ALPN**: 평문 경로 없음, 서버 신원 검증 및 클라이언트 인증서 인가
- **크래시 내성 이어올리기**: 4 MiB마다 `fdatasync` → 매니페스트 동기 기록 → 원자적 교체 → 디렉터리 `fsync`. 복구 시 커밋되지 않은 꼬리 절단
- **무결성**: 입력 전체 및 결과 CSV SHA-256 검증, 결과 캐시 다이제스트 재검증
- **자원 통제**: 고정 워커 풀, 수용 큐, 큐 적체 시간 제한, 디스크 쿼터, TTL 회수
- **운영 안전성**: 워크디렉터리 소유자·심링크 검증과 배타 잠금, 신속한 `SIGTERM` 종료

## 6. 한계 및 주의

정직하게 남겨두는 항목입니다.

1. **제공 로그의 로컬 보관**: `BYDA_Test_Log_500MB.log`는 506,286,814바이트로 GitHub 단일 파일 제한을 넘으므로 gitignore된 `testdata/`에만 둡니다. SHA-256은 `5e84d24fd0c5f5db7280f1b7bd74fc846c7771dfdc43337b908619a67655d88e`입니다. 파서는 이 BYDA 형식과 기존 회귀 형식을 모두 지원합니다.
2. **ThreadSanitizer는 CI에서만 검증**: 개발 환경(WSL2) 커널에서 TSan 런타임이 기동하지 않아 GitHub Actions Ubuntu 러너에서 검증했습니다(통과, 레이스 미검출).
3. **Windows GUI 배포본은 zig 크로스컴파일 산출물**: 실제 Windows에서 실행·전송을 확인했으며, MSVC 네이티브 빌드 경로도 유지합니다.
4. **개발용 PKI**: `scripts/generate_test_certs.sh`가 만드는 인증서는 테스트 전용입니다. 운영에서는 조직 PKI와 보호된 키 저장소를 사용해야 합니다.
